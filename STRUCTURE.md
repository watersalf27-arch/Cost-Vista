# Cost Vista — Project Structure & Conventions

> Brand: **Cost Vista** — "Compare. Plan. Live Better." Navy + gold, royal/premium
> positioning, matching the reference logo (globe + city skyline + rising chart).

This doc is the source of truth for every page/tool added to this repo, the same way
DAILYKITBOX-STRUCTURE.md worked for DailyKitBox. Follow it exactly so 30+ (eventually
150) country pages, city pages, and dozens of tools all stay visually and technically
consistent.

## 1. Hosting model

- **Static frontend**: plain HTML/CSS/JS, GitHub Pages compatible (free subdomain for now,
  custom domain can be attached later via CNAME with zero code changes).
- **Country/city pages are pre-built static HTML**, generated at build time from JSON data
  files (`/data/countries/*.json`, `/data/cities/*.json`) + a shared template
  (`/scripts/templates/country.html`, `/scripts/templates/city.html`) via
  `/scripts/build.js` (Node, run locally or in a GitHub Action on push). Required for real
  SEO/AEO — crawlers and AI answer engines need real static HTML, not client-rendered JS.
- **Serverless backend**: Cloudflare Workers (`/workers/`) handle anything needing a secret
  key or live computation — currency conversion, AI summaries, analytics logging — same
  pattern as DailyKitBox's conversion proxy.

## 2. Repo layout

```
/index.html                    homepage
/about/index.html, /privacy/index.html, /terms/index.html, /contact/index.html   trust pages (required before AdSense)
/countries/index.html          countries directory/listing
/countries/<slug>/index.html   generated — one folder per country
/cities/<slug>/index.html      generated — one folder per city
/tools/<tool-name>/index.html  hand-built interactive tools (flat, no nested /tools/ inside itself)
/data/countries/<code>.json    source data per country (drives generated pages)
/data/cities/<slug>.json       source data per city
/scripts/build.js              generates /countries and /cities from /data + templates
/scripts/templates/            HTML templates used by build.js
/assets/css/style.css          shared design system (tokens, base, components)
/assets/css/<page>.css         page/tool-specific styles
/assets/js/main.js             shared: nav, theme toggle, search
/assets/js/<page>.js           page/tool-specific scripts
/workers/<name>-worker.js      one Cloudflare Worker per backend function
/robots.txt, /sitemap.xml      root-level, sitemap regenerated by build.js from /data
```

## 3. Naming rule

Tool/page folder name, CSS filename, JS filename, and CSS class-prefix all match, e.g.
`cost-of-living-calculator/` → `assets/css/cost-of-living-calculator.css` →
`assets/js/cost-of-living-calculator.js` → prefix `col-`.

Prefixes used so far: `cv-` (shared/root tokens + homepage + nav/footer), `col-` (cost of
living calculator), `cty-` (country page template), `cit-` (city page template).

## 4. Design tokens (see assets/css/style.css for full set)

- Navy `#0A1F35` / Navy Deep `#050F1D` / Navy Soft `#123253` — dark bg, hero, footer
- Gold `#C9A227` / Gold Light `#F0CC6B` / Gold Deep `#A9841E` — primary accent, buttons, wordmark "VISTA"
- Emerald `#1E8A5F` — used ONLY as a functional "affordable/positive" signal (e.g. a
  cheap-city badge), never decoratively — keeps the navy+gold identity from getting diluted
- Mist `#F7F5F0` (warm off-white) — light surface; Slate `#1C2A3A` — body text
- Signature gradients: gold `linear-gradient(135deg, var(--cv-gold-deep), var(--cv-gold), var(--cv-gold-light))`,
  navy `linear-gradient(160deg, var(--cv-navy-deep), var(--cv-navy), var(--cv-navy-soft))`
- Glass surfaces: light `rgba(255,255,255,.68)` + gold-tinted border; dark `rgba(255,255,255,.07)` + gold-tinted border
- Fonts: **Fraunces** (display/headlines — gives the serif elegance a "royal" brand needs),
  **Plus Jakarta Sans** (body/UI), **IBM Plex Mono** (numbers/data in calculators and price tables)
- Dark mode via `[data-theme="dark"]` on `<html>` (JS-set), matching DailyKitBox's pattern.
- Logo mark: circular navy badge, gold ring accent, used at 36px in nav; full illustrated
  version (globe/skyline/chart) reserved for hero and favicon/social previews.

## 5. Data schema (per country JSON — see /data/countries/pakistan.json and usa.json for filled examples)

```
{
  "code", "slug", "name", "flag_emoji", "region", "capital", "currency", "language",
  "population", "cost_index" (0-100 relative), "rent_index", "safety_score", "internet_mbps",
  "healthcare_score", "avg_salary_usd", "visa_note",
  "monthly_costs": { "single": n, "couple": n, "family": n },
  "categories": { "rent": n, "food": n, "transport": n, "utilities": n, "healthcare": n },
  "top_cities": [slugs...],
  "article": { long-form sections used to render the 1500+ word page }
}
```

City JSON mirrors this at city level plus `country_slug` for linking back.

## 6. Build order (how we're rolling this out)

1. Rebrand + design system + homepage + trust pages (**this batch**)
2. Build pipeline (`build.js` + templates) + first country pages as proof of concept (**this batch**)
3. Flagship tool: Cost of Living Calculator (**this batch**)
4. Remaining ~30-country batch, in smaller sub-batches for quality control
5. Cloudflare Worker: currency rates + AI summary proxy
6. Cities, remaining calculators, AI features, analytics/bookmarks, monetization slots
7. Apply for AdSense once ~20-30 quality pages + tool + trust pages are live and indexed

## 7. SEO head order (same as DailyKitBox)

meta/canonical → geo/content-language → OG/Twitter → favicon+manifest →
JSON-LD (WebApplication/TravelAction on tools, Place/FAQPage/BreadcrumbList on
country & city pages, Organization + WebSite site-wide).

## 8. AdSense-readiness checklist (tracked here, not skipped)

- [ ] Privacy Policy, Terms, About, Contact pages live
- [ ] 20-30 genuinely useful, original content pages (no thin/spun content)
- [ ] Clean nav, mobile-friendly, fast-loading, no broken links
- [ ] Site verified in Google Search Console, sitemap submitted
- [ ] Custom domain attached (recommended before applying, not required to build)
